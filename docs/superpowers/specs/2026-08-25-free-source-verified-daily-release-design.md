# 免费公开源的已验证日更发布设计

## 目标与非目标

目标是在不采购商业数据、不回填历史、也不启用交易执行模型的条件下，让每日看板只发布经验证的批次。每个已发布批次必须可回答：使用了哪两个来源、对应哪一个完成交易日、哪些字段按低频披露允许滞后、以及何时发布。

非目标是承诺任何免费网页接口永不故障，也不是将 Module 7 候选名册变成交易指令。免费公开网页接口没有稳定性承诺；系统保证的是失败不误导，而不是在来源失效时编造完整数据。

## 已确认的发布规则

- 香港时间 06:15 开始更新；首轮失败时，在 06:35、06:55 与不晚于 07:15 的窗口重试。
- P0 任一项未通过双源核验，07:15 后不发布新的研究结论、行业排名、仓位结论或行动措辞。
- 失败时保留最后一个 `releaseStatus == "已验证发布"` 的数据批次；页面和 Notion 明确显示本次失败时间、失败字段和该已验证批次的业务日期。
- A 股的业务日期是最近一个已完成且在交易日历中开放的 A 股交易日；06:15 不是当天收盘数据的承诺时间。
- 新闻、FRED 等低频来源以各自披露频率的最大允许滞后校验；其原始日期必须可见。
- Module 7 继续仅作为代码候选名册；没有已验证的当日行情、研究覆盖和执行模型时，不生成行动动作。

### 时间语义

- `runDate` 是香港时间开始运行的自然日；`businessDate` 是该时点以前最近一个显式开放的 A 股交易日。2026-08-25 06:15 HKT 的 `runDate` 是 2026-08-25，`businessDate` 必须是 2026-08-24（若 8 月 24 日为开放日）。
- 看板主标题、批次键、行业行情日期、持仓行情日期使用 `businessDate`；顶部“自动批次”另显示 `runDate` 和 `startedAt`，两者不得混写。
- 定时表达式固定为 `15 22 * * 0-4`（UTC），即香港时间周一至周五 06:15；中国休市日由显式交易日历在程序内跳过，不用周末逻辑推断。

## 数据分级与校验标准

| 分级 | 内容 | 通过标准 | 失败后的发布行为 |
|---|---|---|---|
| P0 | 交易日历、2 只持仓股票、12 只基金、行业前 10、风险闸门 | 代码完整；来源日期符合各自频率；两条独立公开来源可比字段一致；不存在 `待核验`、周末或超期日期 | 整个新批次不发布 |
| P1 | 财经新闻前 10、专家观点、低频宏观明细 | 来源和日期存在，未超过该字段的最大允许滞后 | 可保留上一已验证记录，但不能触发新的行动语 |
| P2 | 7C/7D 代码名册、7E 替代关系 | 名册代码合法且状态明确 | 继续显示名册；执行动作为空 |

### P0 字段规则

1. **股票与 ETF 市价**：每个证券的代码、完成交易日、昨收、收盘价与日涨跌幅必须由至少两个来源返回。收盘价按绝对差不超过 0.01 元或相对差不超过 0.15%（取较大容差）判为一致；日涨跌幅差不超过 0.10 个百分点。超过阈值或任一必要字段缺失即失败。
2. **基金净值**：12 个基金代码必须完整。普通境内基金的 `navDate` 必须是最近完成交易日或基金管理人实际披露的同日；QDII 允许其基金管理人披露页面所示的较早 `navDate`，但日期、来源和“QDII 披露滞后”必须同时展示。两源净值差超过 0.0001 或净值日期不一致时失败。
3. **行业前 10**：东方财富板块扫描仍负责“全市场发现”；每个发布入选行业必须映射到预定义的指数或 ETF 基准篮子。基准篮子的完成交易日、涨跌方向和可用性必须由独立行情源复核。东方财富扫描失败、映射缺失或基准校验失败时，当天不产生新的“全市场前10”。
4. **风险闸门**：每项风险指标必须有 `sourceDate` 与频率策略。日频价格/利率字段不可早于规定窗口；周频、月频指标在其发布时间窗内有效。任何指标日期待核验或超出该指标窗口时，风险闸门为 P0 失败。
5. **交易日历**：只允许使用显式开放日。周末、官方休市日、未来日期和无日历记录日期都不构成有效业务日期。

### 最大允许滞后

| 字段类别 | 最大允许滞后 | 逾期行为 |
|---|---:|---|
| A 股股票、A 股 ETF、行业基准 | 0 个业务日（必须等于 `businessDate`） | P0 失败 |
| 普通境内基金净值 | 0 个业务日（必须等于 `businessDate`） | P0 失败 |
| QDII 基金净值 | 5 个业务日，且必须来自基金管理人官方页面 | P0 失败 |
| FRED 日频、日度利率/波动率 | 5 个自然日 | P0 失败 |
| FRED 周频 | 10 个自然日 | P0 失败 |
| FRED 月频、北向月度统计、估值月度字段 | 45 个自然日 | P0 失败 |
| 财经新闻 | 72 小时 | P1：保留日期，不生成新行动语 |
| 专家观点 | 90 个自然日 | P1：保留日期，不生成新行动语 |

## 免费来源策略

| 数据 | 主源 | 独立校验/备用 | 用途与限制 |
|---|---|---|---|
| A 股、ETF 报价 | 东方财富公开行情 | 腾讯财经公开行情；新浪财经公开行情 | 三者都是公开网页接口；两源一致才可用，不能视为有 SLA 的商业 API |
| 交易日、交易所统计、沪深港通、ETF 公告 | 上交所/深交所公开披露 | 中证指数公开指数资料 | 用于日历与市场收市后的权威校验，不用来伪造逐笔报价 |
| 基金净值 | 东方财富基金历史净值 | 每只基金预配置的基金管理人官方净值页 | 不从搜索结果临时猜测基金官网；代码与官方 URL 的映射是受版本控制的配置 |
| 行业基准 | 东方财富板块扫描 | 映射后的行业指数/ETF 公开行情 | 仅作方向和有效日期校验；无映射不发布新排名 |
| 宏观 | FRED 等原始公开发布方 | 频率/发布日期校验 | 允许低频，但禁止显示为当日数据 |

上交所公开数据目录包含市场日历、行情和 ETF/基金数据栏目；深交所收市后披露交易统计；它们是交易日与披露时间的校验依据，而不是免费实时逐证券行情 SLA。腾讯、新浪公开行情只作为无 SLA 的独立网页校验源。

## 批次、重试与发布状态

每次 06:15 运行生成一个不覆盖现有已发布数据的候选批次。候选批次包括 `batchId`、`startedAt`、`attempt`、`businessDate`、每个来源响应摘要和校验结果。

```text
06:15  生成候选批次并完成首轮校验；任何网络调用的完成时间不得越过 07:15
06:35  仅重试失败的来源和依赖它们的 P0 校验
06:55  仅重试仍失败的来源和依赖它们的 P0 校验
07:15  最后一轮校验：通过则发布；失败则写入失败状态，不替换已验证批次
```

候选批次状态仅允许：`采集中`、`待重试`、`已验证发布`、`发布失败`。只有 `已验证发布` 可以成为 GitHub Pages 的当前数据，或成为 Notion 可见页面的最新研究批次。

失败状态单独存储，至少包含：`attemptedAt`、`deadlineAt`、`businessDate`、`failedModules`、`failedFields`、`lastVerifiedBatchId`、`lastVerifiedBusinessDate` 和不含密钥的来源错误摘要。

## 跨系统一致性

GitHub Pages、原始数据与 Notion 不是同一个事务系统，不能承诺物理上的同时写入。设计采用同一 `batchId` 与显式发布状态避免“看起来相同但实际不同”：

1. 所有候选数据先在 Actions runner 内存中验证，不改 `data/market-data.json`。
2. 校验通过后生成静态看板与待发布 Notion 区块；区块中带候选 `batchId` 和 `发布中` 标识。
3. Notion 区块写入成功后，提交并推送 GitHub Pages 数据与静态构建产物。
4. 推送成功后执行一次 Notion 状态收敛，将相同 `batchId` 标记为 `已验证发布`。
5. 任一阶段失败均不将候选标记为已发布；下一次运行先检查并收敛该 `batchId`，不创建第二份相同业务日期的行动结论。

这保证短暂故障最多导致“候选/失败状态”，不会导致一端把未验证数据称为已发布。

## 用户可见内容

成功时：显示 `已验证发布`、批次 ID、业务日期、各 P0 来源核验数量和 P1 合法滞后说明。

失败时：显示 `今日批次未发布`、最后已验证业务日期、失败模块、下一次尝试时间或 07:15 截止结果。所有仓位、加减仓、追高/退出等行动词替换为 `数据核验`。

字段完整度仍可展示，但必须与 `发布状态` 分开；完整度不能覆盖 P0 校验失败。

## 验收标准

1. 香港周一至周五 06:15 执行；香港周六不运行；官方休市日只记录跳过状态。
2. P0 双源都通过时，GitHub Pages、`market-data.json` 与 Notion 最终显示同一 `batchId` 和 `已验证发布`。
3. 任一 P0 双源缺失、日期非法或超容差时，07:15 前重试；到期后不替换最后已验证数据。
4. 失败页面与 Notion 均包含失败字段、最后已验证业务日期和 `数据核验`，且不含行动词。
5. QDII 和 FRED 等低频字段按真实披露日期通过频率校验，不被伪装为日频更新。
6. 全量单元测试、候选批次 dry-run、前端生产构建和 Notion 区块夹具测试均通过后，才允许申请发布。
